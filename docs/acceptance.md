# 验收矩阵与检查入口

以下是验收目标与检查入口。实测结果和隔离目标见 [执行进度](../PROGRESS.md)；表格中的条件本身不代表测试通过。

## 统一检查入口

`scripts/check.sh` 支持 backend、frontend、e2e、all 参数。backend 运行 Ruff、mypy、pytest，frontend 运行 ESLint、TypeScript 检查、Vitest 和生产构建；e2e 在独立 PostgreSQL 与上传临时文件系统上运行 Playwright；all 串行运行全部。使用受控容器和锁定依赖，不依赖宿主机恰好安装的版本。

检查必须失败即非零退出，禁止 `|| true`。pytest/Vitest 没有收集测试、关键集成测试被跳过或 Docker 不可用时不能伪装成功；尚未建立 e2e 的早期阶段只执行适用子项并记录 e2e 未就绪。检查脚本负责启动或明确核验独立测试 PostgreSQL，拒绝连接应用数据卷。测试中 mock 外部非核心边界可以，但数据库、编号、上传校验和搜索验收不能整体替换为 mock。

README 记录实际可运行命令。阶段 01 已通过隔离失败断言确认检查入口返回非零，再移除该临时断言并重新通过。业务测试不可为通过而删减或放宽。

## 验收场景

| ID | 阶段 | 场景与通过条件 |
|---|---|---|
| ENV-01 | 00 | 明确 Docker CLI、Compose、引擎、端口及实际版本；缺失不被当作成功 |
| BOOT-01 | 01 | 空环境启动；迁移先完成；浏览器和 live/ready 可访问；db/backend 无宿主发布端口 |
| CHECK-01 | 01 | 后端/前端检查有真实测试；故意失败后退出非零；恢复后通过 |
| DB-01 | 02 | 空 PostgreSQL Alembic upgrade head 成功，全部外键与唯一约束存在 |
| NUM-01 | 02 | 至少 50 个并发创建，用独立连接/事务，编号唯一；删除后新建不复用 |
| NUM-02 | 02 | 样品编号按时区跨年；记录本本内编号跨年不重置；日期修改不改编号；转移/恢复领新号，超补零宽度仍增长 |
| CRUD-01 | 03 | 创建/更新/查询/删除/恢复实验和化合物，非法字段拒绝；事务失败无半条记录 |
| REL-01 | 03 | 显式关联唯一；解除不影响其他来源；引用化合物删除 409 |
| TAG-01 | 03 | 规范化重复标签拒绝；移除标签只影响分类 |
| VER-01 | 03..07 | 同版本的两次写入仅一次成功；过期版本 409，已有数据不被覆盖 |
| RXN-01 | 04 | 一个实验两个反应、重复化合物分次加料、各角色、产品收率均可保存 |
| SAMPLE-01 | 04 | 混合物可无 compound；数量/单位成对；跨实验 sample 引用拒绝 |
| REL-02 | 04 | explicit/sample/reaction 三来源并集去重，反向查询一致；分页不漏不重 |
| FILE-01 | 05 | 所有支持类型上传/下载；独立 hashlib 结果与存储 SHA256 一致，字节不变 |
| FILE-02 | 05 | 超限、空文件、伪装类型、NUL、路径穿越、符号链接逃逸失败且无有效元数据 |
| FILE-03 | 05 | 同名/同哈希允许独立上传，不覆盖；事务提交失败清理新文件；中断不假成功 |
| FILE-04 | 05 | 不能给已删除父级上传；软删除文件不可下载但物理存在；样品删除后实验仍可访问文件 |
| SEARCH-01 | 06 | 中文、编号、名称、SMILES 特殊字符按字面检索；注入字符串不改变 SQL |
| SEARCH-02 | 06 | 空查询拒绝；各组分页与数量正确；已删除及父级隐藏记录不出现在结果 |
| SUMMARY-01 | 06 | 固定夹具的摘要准确、缺失显示未记录；不含删除记录；内容不变时 revision 不变 |
| DASH-01 | 06 | 有效总数准确，最近列表不超过五条且顺序稳定 |
| DELETE-01 | 07 | 先删子项再删父项再恢复父项，子项保持删除；无效引用阻止恢复 |
| RACE-01 | 07 | 创建引用与删除父/Compound 并发执行，不能提交悬空有效关系 |
| PERSIST-01 | 07 | 重启三服务后数据/文件存在且内容一致 |
| BACKUP-01 | 07 | 隔离还原后编号、关联、软删除和所有文件哈希一致；新建编号不复用 |
| BACKUP-02 | 07 | 缺失/篡改文件或 dump 失败时工具非零、无成功标记，原服务状态恢复 |
| E2E-01 | 08 | 浏览器完成化合物→实验→样品/反应→文件→搜索→摘要→删除→恢复 |
| UI-01 | 08 | 1280×800/1440×900、浅深色、长文本、键盘、错误和空状态可用 |
| DOC-01 | 08 | 按 README 从空环境成功启动；记录真实依赖、命令、备份/恢复和已知限制 |

## 证据要求

每项记录测试名称/文件、执行命令、日期、退出码和简短结果。截图用于界面验收，不能替代业务断言。恢复演练记录隔离目标、清单比较及校验结果。没有 Docker、未执行或跳过时明确写“未验证”，不能写“基本通过”。

全量覆盖率不设凭空数字；先建立有意义的基线，后续不能通过删除测试、调整排除项、增加 skip 或降低阈值伪造进步。对已确认规范的任何改变必须记录原因，不能临时改变判卷标准以掩盖缺陷。
