# 注册、登录与个人数据空间

账号使用 3–40 位英文字母、数字、点、下划线或连字符，忽略大小写；姓名或昵称单独显示。密码为 12–128 个字符，使用独立随机盐的 scrypt 保存，不存明文。

## 首次使用与旧数据

升级后未登录不能访问业务 API。首个注册账号在同一事务中接收所有尚无归属的记录，包含回收站；注册不会修改原编号、实验内容、关联或上传文件。首次注册必须由本机所有者完成，完成前保持服务仅监听回环地址。后续账号拥有空的个人空间和“我的实验”记录本，不共享旧记录。

本次不改变本机网络边界，也不提供课题组共享、角色管理、邮箱验证、邮件找回密码或公网部署。请使用密码管理器保管密码；已登录后可点击侧栏或窄屏顶部的用户名，从账号菜单选择修改密码或退出登录。修改密码在独立弹窗中完成，关闭时清除输入，保持当前页面。

## 会话与访问限制

- 注册成功直接登录；登录状态最长保持七天。随机会话令牌仅放在 HttpOnly、SameSite=Strict Cookie 中，数据库保存 SHA256 摘要。退出会删除服务端会话；修改密码会撤销该账号全部旧会话，并给当前浏览器发新会话。
- `/api/auth/register`、`login`、`me`、`logout`、`password` 提供账号接口。业务接口要求有效会话；失效返回 401，前端回到登录页。健康探针与 API 文档仍可无登录访问。
- 所有写入请求必须带 `X-RDMS-Request: 1`；跨站 Origin 和非法 Host 仍返回 403。该请求头与未启用跨域访问、Origin 检查共同防止浏览器跨站提交，包括登录和注册。命令行使用者也须携带请求头及会话 Cookie。
- 注册、登录、修改密码通过 PostgreSQL 计数限流，每账号/操作 15 次、每来源/操作 60 次，窗口为 15 分钟，超限返回 429。当前来源为直接连接的地址，不信任转发头；本机 nginx 代理后的访问会共用来源额度。未来公网代理需另外设计可信来源识别。
- 本机 HTTP 使用 `AUTH_COOKIE_SECURE=false`，未来 HTTPS 部署必须设置为 true，且另外适配域名和 Origin 检查；这个选项本身不会启用公网访问。

## 数据库隔离

迁移 `7d3a1b9c602e` 增加账号、会话、限流及数据归属字段。每个业务事务使用受限的 `rdms_member` 数据库角色，并通过事务内账号上下文应用 PostgreSQL 行级安全策略；提交后的新事务重新设置上下文，连接池不会沿用上个账号。列表、详情、搜索、总览、摘要、关联、回收站和下载使用相同隔离规则，越权对象返回 404。

`rdms_member` 不拥有登录权限、超级用户或绕过行级安全的权限，不可读取账号密码表、会话表。迁移连接需要建立并授予该角色的权限；数据库与后端不发布宿主端口。维护工具的数据库连接用于全量备份检查，不走用户 API。

标签名称仅在账号内唯一。原业务编号保持全局唯一，新记录本和样品继续使用原全局取号机制，因此不同账号的编号可能有间隔；编号不代表访问权限。

## 备份与回退

账号、密码摘要、归属与会话表随数据库一起备份，因此备份仍属敏感资料。恢复工具在新数据库建立受限角色、恢复行级策略并重新授予必要权限；恢复完成后撤销旧会话，所有用户需重新登录。原始文件仍需与数据库一起恢复。

存在任何账号时迁移拒绝直接降级，防止删除账号与数据归属。回退应使用迁移前备份、匹配迁移前代码，在新的项目与空目录隔离恢复。

## 检查

`backend/tests/test_auth.py` 使用独立 PostgreSQL 验证会话撤销与过期、密码变更、限流、旧记录归属、跨账号访问与连接池隔离。`frontend/src/features/auth.test.tsx` 验证登录门禁、确认密码和退出失败；`frontend/e2e/auth.spec.ts` 在临时数据库与上传目录中验证真实注册、刷新、退出、重新登录、修改密码、手机布局及跨账号隔离。
