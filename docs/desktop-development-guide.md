# RDMS Mac / Windows 本地应用开发指南

日期：2026-10-19。状态：工作计划，尚未实施桌面化或完成桌面验收。

本文件用于交接给后续开发模型。先阅读本文件，再按阶段执行；不要把规划中的能力描述为已有功能。用户当前授权是编写指南，本文不是已经创建工作树、发布安装包或改变数据存储方案的证明。

## 1. 目标与范围

交付可安装、可启动、可保存实验数据的 Mac 和 Windows 本地桌面应用。复用现有业务界面和后端；正式数据保存在用户设备上，换设备登录不自动取得原设备数据。

第一版目标：

- 用户不需要手动安装 Python、Node、PostgreSQL 或 Docker，也不需要打开终端启动应用。
- 安装后可以创建实验、处理化合物结构、管理反应与投料、上传下载附件、搜索、删除恢复。
- 核心功能在断网时可用；联网 CAS / 理化性质查询单独提示并可禁用。
- 退出、重启、升级和卸载均不擅自删除用户资料。
- 提供完整备份、校验、隔离恢复与设备迁移入口。
- Mac / Windows 共用业务源码与版本号，分别构建和验证安装包。

暂不实现：iOS / Android 客户端、云端账号中心、付费授权、团队共享、实时同步、公共云托管、自动更新下载。沿用现有本地账号；自动更新可在手动升级路径稳定后另行规划。

“本地应用”不等于“全面重写为原生界面”。优先复用 React 界面与 Python 服务。桌面外壳、运行环境和数据库打包方案须先验证再定案。

## 3. 不可突破的边界

- 不连接、迁移、覆盖或测试写入当前真实数据库、`data/uploads` 和真实备份。
- 不复制真实 `.env`、密码、CAS 密钥、账号、附件到工作树、测试包或安装包。
- 不运行常规 `docker compose down -v`、全局清理、未经范围确认的删除命令。
- 业务数据结构变更必须使用 Alembic，不用 `create_all` 替代迁移。
- 保留现有 Compose 本机模式：前端回环监听，后端与数据库不发布宿主端口，保留 Host / Origin 检查。
- 非 Docker 桌面模式需要进程间本地通信，必须先写明与现有约定的关系。优先本地 socket / pipe；若须回环 TCP，限定回环地址、认证与端口归属，并先取得对该桌面模式边界的明确确认。不得通过绑定 `0.0.0.0` 或删除来源检查绕过问题。
- 不因桌面壳使用 `file://` 就允许任意 Origin、`null` Origin 或宽泛 CORS。静态页面和 API 的同源方案须在阶段 1 定案。
- 不把“无公网监听”说成“本机其他进程无法访问”；本地接口仍需要认证与最小暴露。
- 不自动上传科研内容、崩溃附件或遥测。CAS 查询等已有外部调用必须明确列出发送字段和触发动作。
- 本地存储不等于加密；未经实施和测试不得承诺数据库或附件已加密。

## 4. 仓库、分支和工作树

推荐同一个 Git 仓库、独立工作树，避免复制成两个长期分叉的项目：

```text
Code_Project/
├── RDMS/           原工作目录，继续维护现有版本
└── RDMS-desktop/   推荐的桌面开发目录；实际路径以创建工具结果为准
```

推荐桌面分支：`codex/desktop-app`。子任务可使用 `codex/desktop-任务名`，完成后汇入桌面开发分支。

阶段 0 必须处理的现实问题：编写本指南时，原工作区已有多处未提交修改和未跟踪演示文件。工作树不会自动带入这些内容，不能直接从旧 HEAD 创建后声称已继承最新版本。

执行顺序：

1. 检查 `git status --short`、当前分支、提交与已有工作树；记录结果。
2. 审查现有修改，区分源码、演示、文档与生成产物；不丢弃、不重写用户改动，不执行 `reset --hard`、`clean` 或隐式 stash。
3. 将确定需要继承的源码及文档整理为基线提交；不要未经审查执行 `git add .`。有不明归属修改时，先列明再处理。
4. 记录基线提交 ID，从它创建桌面分支与独立工作树；使用桌面应用的工作树工具时遵守其路径与注册规则。
5. 为工作树设置独立的开发数据根、测试目录和端口。注意 Compose 配置固定项目名为 `rdms`，仅换目录不保证隔离；桌面开发不得直接启动默认正式 Compose 项目。
6. 在新目录验证代码与基线一致。不存在的未跟踪文件必须从已审查基线继承，不从真实运行目录随手复制。

本文不要求现在移动现有项目、创建工作树或合并分支。后续收到开发任务时执行上述流程。

## 6. 分阶段执行

### 阶段 0：建立安全基线

**工作**：完成第 4 节；列出现有数据位置与不可触碰范围，但不打印秘密；确认工具、磁盘空间、Mac 架构和是否有 Windows 测试环境。

**交付**：基线提交、分支和工作树路径；独立数据根；当前测试结果或明确的未运行原因。

**通过条件**：没有丢失原工作区改动；没有将真实资料带入开发树；能够解释新树从哪个版本开始。

### 阶段 1：最小打包与技术定案

本阶段先解决可运行性，不扩展业务功能。

**工作**：

1. 比较 Electron、Tauri 等桌面壳对现有 React、Python sidecar、安装与维护的实际成本。依据官方资料和最小实验选择一个，不同时开发两套完整方案。
2. 验证 Python、RDKit、psycopg 和 PostgreSQL 的目标平台分发方式、依赖、许可证及升级限制；记录具体版本与下载来源。
3. PostgreSQL 是优先保持的方案。现有系统依赖行级安全、角色、序列和 PostgreSQL 测试，不能为打包方便直接改为 SQLite。
4. 若打包 PostgreSQL 无法满足目标，输出可复现失败和替代方案的影响，再决定；数据库替换属于独立架构工作，不能偷偷实施。
5. 确定本地通信、静态资源和 API 同源、会话 Cookie、动态端口、数据库认证、单实例锁及日志目录。
6. 明确目标矩阵：至少验证 macOS Apple Silicon 与 Windows x64；实际环境不足则标记未验收。Intel Mac / Windows ARM 是否支持必须单独标明，不因文件名包含 Mac / Windows 就宣称支持全部架构。
7. 在两种目标系统安装最小包：无需用户安装开发环境，创建一条合成实验，退出，重开，确认记录存在；执行一次 RDKit 结构解析和附件写入读取。

**交付**：决策记录、可复现构建步骤、最小包和实测证据。

**通过条件**：两种目标系统均完成上述闭环。只有单平台成功时可以继续独立实现，但不能宣布跨平台打包完成。

### 阶段 2：应用外壳与服务生命周期

**工作**：

- 正确顺序启动数据库、迁移、API、窗口；API ready 后再进入业务界面。
- 处理慢启动、端口冲突、后台异常退出、重复打开、窗口关闭和系统关机。
- 只管理本应用启动且已验证身份的进程；不能按进程名字批量杀 PostgreSQL / Python。
- 错误界面说明问题与可执行恢复动作，不无限显示加载动画。
- 桌面界面限制导航与新窗口；不向网页暴露任意 shell、文件系统或系统执行能力；外部链接走受控系统浏览器入口。
- 原有 Web / Docker 模式仍可构建与运行。

**交付**：可完整操作业务的桌面开发版本、进程管理测试及安全边界说明。

**通过条件**：重复启动不会出现两套写同一数据目录的服务；关闭后不留下失控进程；端口被占用时不连接陌生服务；默认不监听局域网地址。

### 阶段 3：数据目录、账号与备份迁移

**工作**：

- 使用操作系统标准的应用数据目录 API；安装资源与可写数据分开，禁止数据库写入安装目录或源码目录。
- 分离正式、开发、测试的数据根；使用者选择外部目录时验证权限和空间。
- 初始化生成独立凭据，不使用 Compose 示例密码；保护凭据文件及日志，保留本地账号隔离。
- 提供备份、校验、导入到空目标的界面入口。完整备份必须包括数据库、附件、版本和哈希清单。
- 抽取或适配现有备份逻辑，保留原 Compose 工具；桌面恢复不能假装调用 Compose 就已经完成。
- 设置自动备份策略、失败提醒、备份空间上限和保留规则；自动清理仅限被明确识别的应用备份，不能删除用户任意文件。
- 支持从旧 RDMS 备份迁移，必须先用合成数据验证匹配版本恢复与升级；迁移到新目录，原备份和来源保持不变。
- 区分磁盘内副本和独立介质备份，不承诺同盘备份能防磁盘损坏。

**通过条件**：重启后数据和附件哈希一致；备份缺失或损坏会失败；非空恢复目标被拒绝；没有备份权限时明确报错；换电脑只有主动导入后才出现原数据。

### 阶段 4：版本、升级和安装包

**工作**：

- 选定唯一的产品版本号来源，让桌面包、关于页面、发布清单读取它；现有前端 package 的 `0.1.0` 不代表桌面版已经发布。
- 建议首测 `0.1.0-beta.1`，首个稳定版本视验收结果定；Mac / Windows 同一产品版本对应同一源码提交。
- 保留 Alembic 作为数据库版本来源。发布清单列出产品版本、提交 ID、迁移 head、运行时版本、系统/架构、安装包 SHA256。
- 升级前备份；检测数据库版本兼容性；迁移失败时不进入可写业务界面，不自动降级数据库。
- 安装到新应用版本不覆盖数据；卸载默认保留数据。恢复需要匹配的应用版本和完整备份，不能只回退 Git 或安装旧包。
- 核实 PostgreSQL 主版本更新是否需要专门升级流程，不把二进制替换当成数据库升级。
- 区分内部未签名测试包与正式分发包；正式 Mac 包完成签名与公证，Windows 完成发布签名验证。所需证书、账号和费用缺失时记录阻塞，不要求关闭系统安全功能来冒充验收。
- 核查捆绑组件许可证与必要声明；检查安装包不含真实资料、密钥、示例账号或演示数据。

**通过条件**：全新安装、覆盖升级、升级失败恢复、卸载后保留数据均验证；同一版本安装包不可悄悄替换，变更必须生成新版本。

### 阶段 5：跨平台验收与交接

按第 7 节完成验收；修复后复测受到影响的流程。发布候选版本更新 README、CHANGELOG、PROGRESS 与验收文档，再提交和创建对应标签。未经用户明确要求，不自动推送、发布下载链接或公开产品。

**交付**：两平台安装包、校验值、发布清单、用户安装/备份/恢复说明、已知限制、可追溯验收结果。

## 7. 验收矩阵

原有 `scripts/check.sh all` 必须保留并通过：后端使用独立 PostgreSQL、前端检查、隔离浏览器 E2E。该入口不能代替原生安装包测试；不能因 Windows 缺少 shell 而删掉原有检查，可在适当构建环境执行，同时另做 Windows 本机验收。

| 编号 | 场景 | 通过标准 |
|---|---|---|
| D01 | 干净系统安装 | 没有开发工具和 Docker，也能安装启动 |
| D02 | 核心业务 | 实验→化合物→投料/产物→附件→搜索→删除恢复闭环正确 |
| D03 | 离线 | 断网后可登录本地账号、编辑、结构计算、读取附件；外部查询明确不可用 |
| D04 | 持久化 | 正常退出、进程异常后重启，已确认提交记录仍在；异常只对测试进程注入 |
| D05 | 文件 | 中文、空格路径，非管理员用户，大文件上限、上传中断、下载哈希一致 |
| D06 | 数据安全 | 备份恢复完整、非空目标拒绝、损坏备份拒绝，不覆盖来源 |
| D07 | 生命周期 | 重复打开、端口占用、数据库启动失败、服务异常均有明确反馈 |
| D08 | 升级 | 从上个受支持版本含数据升级成功；失败后可按文档恢复 |
| D09 | 权限与入口 | 本机边界有效，跨站写入拒绝，本地账号间不能读附件或记录 |
| D10 | 网络隐私 | 禁用联网查询后，核心流程无科研内容外发；检查实际请求而非仅看按钮 |
| D11 | 系统行为 | 睡眠唤醒、关闭重开、卸载重装后数据行为符合说明 |
| D12 | 分发 | 安装包版本、签名状态、架构、许可证与哈希可核对，无真实数据或秘密 |
| D13 | 存储故障 | 临时测试盘空间不足/无写权限时不假报保存或备份成功；恢复后可继续工作 |

每项分别记录 Mac 和 Windows 的结果：通过 / 失败 / 未执行。提供操作步骤、系统与架构、应用版本、日志和必要截图。编译成功不等于运行成功，模拟浏览器不等于 Windows 安装验证。测试结果未知时写未知，不虚构通过数量。

## 8. 小模型执行协议

每次只领取一个阶段或一个边界清晰的子任务，不同时重写架构、数据库、界面和打包。推荐每次交接附以下任务格式：

```text
先读 AGENTS.md、README.md、PROGRESS.md、docs/verification.md 和
 docs/desktop-development-guide.md。
本次任务：阶段 N 的具体子任务。
工作树：实际绝对路径；分支：实际分支；基线提交：实际 ID。
允许修改：列出当前任务涉及的目录或文件。
禁止：真实数据、原正式服务、无关界面和业务规则变更。
交付：实现、针对性验证、文档与交接记录。
完成条件：引用对应 Dxx，并说明当前阶段要求的证据。
```

执行要求：

1. 先检查工作树与已有修改，再读相关文件；不假设上一模型的最终回复就是事实。
2. 确认依赖版本与目标平台支持，先最小验证再大规模改动。资料必须来自官方文档或源码；不凭印象添加打包参数。
3. 失败时记录命令、退出码、可复现条件和已尝试方案；不得删测试、放宽断言、吞掉异常或用演示数据代替真正持久化。
4. 没有 Windows 环境、证书或权限时继续能独立完成的工作，并明确剩余阻塞；不得伪称已完成跨平台验证。
5. 修改完成运行针对性检查和项目要求的完整检查；纯文档任务做链接与格式检查并说明未运行应用回归。
6. 每个可审查的变更单独提交；提交说明描述实际行为，不写“完成全部”而不提供证据。
7. 更新 PROGRESS 与阶段交接；BLOCKED 仅记录真实阻塞，解除后及时更新。不要修改个人全局记忆或其他项目配置。
8. 遇到数据库替换、联网边界变化、真实数据迁移、购买证书或公开发布等超出当前任务的动作，先完成可审查的方案和证据，再取得必要授权。

每次结束必须交接：当前分支/提交、变更文件、已实现能力、已运行检查及结果、尚未验证项目、阻塞、下一步。不要只写“已完成，请测试”。

## 9. 第一项推荐任务

从阶段 0 开始，整理可继承的基线并建立独立工作树；随后只做阶段 1 的最小打包实验。不要先重做首页、开发团队账号或把 PostgreSQL 换掉。

第一轮真正的里程碑是：在 Mac 与 Windows 上安装应用，离线创建一条合成实验、附加一个测试文件，退出重启仍能读取，且用户没有手动安装运行环境。其余业务完善和正式发布建立在这个证据之上。
