## 执行规则

- 阶段 02 一次设计并迁移核心数据模型；后续若发现必要修正，增加迁移，不能重写已使用的历史迁移。
- 每个业务阶段内部顺序为模型/迁移检查 → repository/service → API → 后端测试 → 前端 → 集成验收；已有模型不重复实现。
- 软删除、版本控制、校验和父级有效性必须随业务功能实现。阶段 07 是整合验收，不是把前面阶段的数据安全推迟实现。
- 00 检查失败时可继续只读梳理或不依赖 Docker 的准备，但不得宣称服务可运行。01 的启动验收未完成不能标记 01 完成。
- 每份独立任务书引用公共规格；执行者必须能读取整个工程文件夹，仅复制任务书正文而不提供文件访问不构成完整上下文。
- 未授权同时运行多个模型写同一工程；如将来并行，先明确共享 schema、接口和 lockfile 的唯一归属。

## 每阶段完成后的记录

PROGRESS.md 增补：阶段、改动、命令与真实结果、使用测试数据库/文件目录、未完成事项、下一任务。BLOCKED.md 为无阻塞时明确写“无”，否则记录问题、证据、影响、已尝试方法和可继续部分。

不得用“先写了代码”代替“通过验收”。同一失败出现三次时必须换诊断方式、缩小复现或隔离原因；无法继续的部分留证据，不反复删除数据或改验收阈值。所有清理仅限本阶段创建且确认不含真实数据的临时资源。

## 后续阶段外事项

RDKit/SMILES 化学校验、结构图、子结构和相似性检索、NMR/LC-MS/HPLC 自动解析、模板、HTE、优化、文献/DOI 接入、AI 助手、自动备份、通用导出、审计和数据版本不在第一版实施。此清单不能作为提前安装依赖或创建大量空模块的理由。
