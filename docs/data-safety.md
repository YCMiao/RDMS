# 数据安全与恢复设计

第一版的首要不变量：原始文件不能被覆盖；普通删除不能物理销毁实验数据；编号不因删除重新发行；备份恢复必须同时恢复元数据和对应文件。

## 存储与网络

Compose 中 PostgreSQL 使用独立命名卷，上传使用 ./data/uploads 持久化挂载，临时上传位于同一文件系统下的 .tmp。数据库及 backend 不发布宿主端口，frontend 只绑定 127.0.0.1。运行数据、备份、.env 忽略到版本控制外。测试使用独立数据库和临时存储根，不得连接真实数据目录。

无用户系统不意味着可暴露公网。启动和 README 明确本地边界，并限制 Host、浏览器跨站写入来源。应用日志不记录实验正文、二进制、数据库密码或完整连接串。

## 上传流程

1. 校验有效 Experiment、可选 Sample 所属关系、字段和文件名；版本无需来自父实验，但事务必须锁定并确认父级仍有效。
2. 只允许扩展名 pdf/csv/txt/png/jpg/jpeg/jdx/dx/zip，大小写不敏感。先按扩展名选择校验器，不信任客户端 MIME。
3. 以固定块大小写入随机临时文件，累加字节数和 SHA256；上限默认 104857600 字节，超过立即终止并删除临时文件。零字节文件拒绝 422。
4. PDF 检查文件头；PNG/JPEG 检查签名并以有像素上限的图像读取器验证；ZIP 检查中央目录可读但不解压；TXT/CSV 支持 UTF-8（含 BOM）及 GB18030，拒绝 NUL 和明显二进制；JCAMP-DX 在文本检查基础上要求 TITLE 与 END 标签。类型检查不等于病毒检测或科学内容有效性验证。
5. 使用随机 UUID 文件名及服务端规范扩展名，存储键如 objects/ab/<uuid>.pdf。拒绝路径分隔符、控制字符，实际存储不使用原名。解析后验证路径在 UPLOAD_ROOT 内，拒绝符号链接逃逸。
6. 校验完成，以硬链接将临时文件原子发布到最终位置，再插入元数据并提交事务；提交失败删除本次新文件，保留错误证据。不能覆盖已存在目标。
7. 返回元数据。上传响应丢失后可能实际已成功，客户端展示需核实，不能默认自动重复提交。

相同 SHA256 允许多条记录和独立文件，第一版不做去重引用计数。不从 ZIP 提取文件，不解析仪器原始数据。客户端 Content-Length 和代理限制只是辅助，服务端流式字节计数才是最终限制。

## 下载与一致性检查

下载只通过 FileAsset ID 查找，先判断实体与父级有效，再解析存储键。返回附件、nosniff、正确的 Content-Type 和安全编码文件名。文件缺失或校验失败返回明确异常并记录，不自动创建空文件冒充原始数据。

阶段 07 已提供 `scripts/rdms_data.py check` 只读检查工具，输出数据库引用但缺失的文件、未被引用的文件、大小不符、SHA256 不符及遗留临时文件；可选择完整哈希检查。工具不得删除、移动或修复文件。正常下载无需每次重新计算全文件哈希。

## 软删除和恢复

遵循 data-model.md 的可见性规则。文件软删除时物理内容保留。恢复父对象不改写子对象自身 deleted_at；恢复子对象必须检查父对象和 Compound。回收站不提供“清空全部”或永久删除功能。涉及真实数据的物理清理必须另行获得明确授权，不能作为失败恢复手段。

## 手动备份

阶段 07 已实现 `scripts/rdms_data.py backup/verify/restore` 和 README 操作步骤；以下是工具遵循的边界。

1. 明确源项目、数据库、上传根和备份目标；目标不得位于上传根内部。
2. 停止 frontend/backend，等待未完成请求结束，确保无应用写入；db 保持运行。
3. 通过 PostgreSQL 配套 pg_dump 导出数据库，包括 NumberCounter 和软删除数据；复制全部正式上传文件（含软删除引用的内容），排除 .tmp 并记录未处理临时文件。
4. 生成清单：时间、应用版本或代码指纹、Alembic revision、数据库版本、文件列表/大小/SHA256、数据库 dump 的 SHA256。
5. 检查所有子步骤退出码，在尚不存在的目标目录生成备份，验证完成并恢复源服务状态后原子写入 SUCCESS 标记；失败不能生成“成功”标记。
6. 在 finally 路径恢复原先运行的服务，不擅自启动此前未运行的服务。保留失败日志且返回非零。

备份复制到同一磁盘仅用于恢复演练，不能等价为抵御磁盘损坏的备份。文档说明用户可把完整备份包复制到外部介质，不自动上传外部服务。

## 恢复及验收

恢复默认只允许到新的隔离 Compose project、独立数据库卷与文件目录；如果目标非空则拒绝，不自动覆盖。先校验备份完整性和 schema 兼容性，再恢复数据库和文件，执行一致性检查后启动应用。工具要求备份 revision 与所用代码 head 完全一致；旧备份必须先使用匹配版本代码隔离恢复，保留原备份后再按正常 Alembic 流程升级。端口由操作者事先确认空闲，工具没有端口占用预检；不盲目降级 schema。

验收包括：编号和关系一致，软删除状态一致，文件数量/大小/哈希一致；恢复后能创建新实验且编号不复用；缺一个文件或篡改一字节时检查必须失败；故意让 dump 命令失败时工具必须非零退出且无成功标记。故障注入仅对隔离夹具进行，不能修改用户原始数据。
