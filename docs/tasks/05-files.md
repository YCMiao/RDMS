# 阶段 05 原始文件上传与下载

你是本阶段执行者。本任务依赖当前工程文件，不依赖此前聊天。先读 PLAN.md、PROGRESS.md、BLOCKED.md，核对实际实现后接续；不要从头重写已完成模块。目标优先级：数据安全与正确性 > 功能闭环 > 易维护 > 速度。

## 前提和约定

- 前置：04 通过。
- 必读：docs/data-safety.md 的存储/上传/下载、docs/data-model.md 的 FileAsset、docs/api-contract.md 文件接口、docs/ui-spec.md、docs/acceptance.md。
- 默认决策：仅本机个人使用，中文界面，Asia/Shanghai；按详细规格实现，不自行加入 AI、多用户或自动科学计算。
- 开工前写不超过 10 行回执：理解的目标、顺序、最大风险。下述验收入口若尚不存在，先按阶段职责建立和亲测，不能把拟定命令说成已运行。

## 修改范围

允许文件业务、对应前端、测试夹具、上传配置及文档；只写专用测试临时目录，不删除或覆盖真实 data/。禁止 ZIP 自动解压、谱图解析、文件自动去重。

## 执行步骤

1. 实现 UUID 存储键、受控相对路径、原名保留和文件元数据；原始内容不允许 PATCH 覆盖。
2. 分块上传、计数、SHA256、默认 100 MiB 上限；按 data-safety.md 校验全部允许类型，不能信任客户端 MIME。
3. 临时文件和正式文件位于同一文件系统；校验后原子移动，插入元数据，提交失败补偿；单独测试失败与进程中断残留边界。
4. 上传前确认有效实验/样品归属并处理并发删除；下载按 ID 查库并验证可见性、路径与符号链接；安全编码 Content-Disposition。
5. 实现实验附件列表、全局 Files 页面、上传/下载/备注与样品关联编辑、软删除恢复；多文件选择拆成单文件请求，逐个显示结果。
6. 使用小型合成文件夹具；超限测试采用降低测试配置上限或流生成，不能把大文件加进代码库。

## 验收

FILE-01..04、VER-01；支持类型真实传输，独立哈希及字节一致；路径穿越/伪装/超限/空文件失败；同名文件不覆盖；提交失败无已注册坏文件；软删除仍保留物理文件。backend/frontend 检查通过。

测试场景编号对应 docs/acceptance.md。记录实际命令、退出码和结果；Docker、数据库或测试工具不可用时写清未验证。不得通过 skip、删除测试、放宽断言、整体 mock 核心业务、吞掉退出码或伪造输出达标。新项目允许新增测试和必要脚本，但不能为迁就缺陷悄悄改既定验收要求。
