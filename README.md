# RDMS

RDMS 是面向个人化学与生命科学研究的本机数据管理系统，提供实验、化合物、标签、样品、反应、原始文件、搜索、总览、规则摘要和回收站，并提供手动备份与隔离恢复工具。

## 运行基线

- Docker Desktop 29.8.0、Docker Compose v5.5.1（阶段 00 实测环境）
- 容器内 Python 3.12.11、Node.js 22.20.0、PostgreSQL 17.6
- 本机只开放 `127.0.0.1:8080`；数据库和后端不发布宿主端口

宿主机的 Node.js、Python 和 PostgreSQL 版本不参与应用运行，无需为本项目修改。

## 配置

第一次运行时复制示例配置并修改本机开发密码：

```sh
cp .env.example .env
```

`.env`、`data/`、`backups/` 和测试产物已被 `.gitignore` 排除。不要把真实数据库密码、上传文件或备份提交到版本控制。

已有数据库卷的安装要启用 CAS 密钥时，只在现有 `.env` 增加 `CAS_COMMON_CHEMISTRY_API_KEY=...`；不要重新复制 `.env.example` 或改动原数据库密码。示例密码只用于首次初始化，不能自动修改已有卷中的密码。

## 启动与检查

在 macOS 上更新应用，可以在 Finder 中双击项目根目录的 **更新 RDMS.app**，点击“更新”。它先构建镜像并验证现有数据库连接，再切换前后端服务；连接失败时会保留正在运行的服务并显示原因。完成后自动打开浏览器，详细过程在项目根目录的 `.rdms-update.log`。更新不会清空数据库或原始文件。

```sh
docker compose up --build -d
docker compose ps
curl --fail http://127.0.0.1:8080/api/health/live
curl --fail http://127.0.0.1:8080/api/health/ready
```

浏览器访问 <http://127.0.0.1:8080>，API 文档位于 <http://127.0.0.1:8080/api/docs>。

若当前终端找不到 `docker`，可将上面命令中的 `docker` 替换为：

```text
/Applications/Docker.app/Contents/Resources/bin/docker
```

运行当前检查：

```sh
scripts/check.sh backend
scripts/check.sh frontend
scripts/check.sh e2e
scripts/check.sh all

# 复用 Docker 构建缓存中的同版本依赖，避免反复下载安装
RDMS_CHECK_CACHED_DEPS=1 scripts/check.sh all
```

后端检查会先清理上次遗留的临时 `db-test` 容器，再使用独立的 `rdms_test` PostgreSQL、数据库 tmpfs 和 `/tmp/rdms-test-uploads`，不会连接应用数据卷。E2E 使用固定的 Playwright 浏览器镜像和独立的 `rdms-stage08-e2e` Compose 项目；测试数据库与上传目录均为容器临时文件系统，重跑时清理该隔离项目的旧容器。`all` 串行执行全部三项。

服务运行后，可从当前 OpenAPI 重新生成前端 API 类型：

```sh
docker compose --profile test run --rm frontend-test npm run generate:api
```

## 当前可用功能

首页以可交互粒子圆盘呈现，桌面保留左侧导航，所有业务入口在当前标签页打开。圆盘未点按时随光标轻微改变视角，拖拽带动旋转，松开后惯性减速；离开首页停止动画，系统减少动态效果时只响应手动旋转。侧栏底部提供浅色／自动／深色及青绿、靛蓝、紫罗兰、琥珀、玫瑰五种全局配色，窄屏通过搜索栏旁的外观设置打开；偏好保存在当前浏览器。独立的顶部导航视觉原型仍保留在 `ui-lab/homepage`（127.0.0.1:18082），与正式应用数据隔离。

实验入口以方块卡片展示 **实验记录本（Lab Notebook）**，可创建、改名、归档，点击进入本内实验列表；“全部实验”支持跨本查看。实验以 `NB001-0001` 等形式在各本内独立连续编号，跨年不重置、删除不复用；新建和复制可选择记录本，详情或列表多选可预览新编号后移入其他本。恢复实验需选择目标本并领取新编号。已有有效实验按原编号顺序统一归入“已有实验”并重新编号，回收站实验不归本，旧 EXP 编号按授权放弃。详细规则和迁移边界见 [实验记录本](docs/notebooks.md)。

实验和化合物详情顶部提供“上一条／下一条”，沿用列表排序、搜索及筛选并跨页切换；从记录本进入时限定本内实验，直接打开实验详情时默认在所属记录本内切换。首尾按钮置灰，返回列表保留筛选与所在页；基础记录、反应条件和打开的投料/产物/溶剂编辑有未保存内容时会提示。

- `/experiments`：创建、筛选、编辑、删除实验。列表支持日期、编号及标题的双向排序；编号按记录本代号和本内序号数值排序，排序在分页前生效。“新建实验”旁可从现有实验复制：在居中窗口中搜索并从下拉菜单选择原实验、设置新标题和日期后创建独立草稿及新编号，按原反应显示顺序复制目的、操作、反应条件、反应物投料与产物记录（含用量、计量比、收率和备注）；观察、结果、结论、样品与附件不带入。一个实验可包含多个反应，反应区每页只显示一个，按现有顺序标为 REACTION 1、REACTION 2 等，通过上一页/下一页切换；有未保存输入时切换会先确认。每个反应依次展示反应总览、01 投料、02 产物与收率、03 溶剂和 04 条件与处理。投料表（系统名称、化学式、CAS、Mw、eq、mmol、mg、mL）不再包含溶剂；溶剂表显示名称、化学式、CAS 号和体积，支持单独添加、编辑、删除及分页，体积可用 mL、L 或 µL 录入并统一按 mL 展示。既有 solvent 组分直接归入溶剂表，保留记录编号、用量、单位及备注；旧的独立溶剂文字仍作为兼容行保留显示，条件保存不覆盖它。点击“添加反应物”才展开详细录入，可按 CAS 自动查找、本机选择或手动填写；投料表不显示结构式和产物栏，总览保留底物 → 产物结构及条件。反应条件保存结果在保存按钮旁显示，字段校验失败会指出字段并保留当前输入；温度可选 °C、K 或描述（如室温、冰浴、回流），时间可选 h、min 或描述（如过夜）。保存后总览、摘要和实验复制保留相应数值、单位或文字；旧的 °C/h 记录继续可编辑。实验基础记录置于反应记录上方，包含标题、日期、状态、目的及默认折叠的统一备注框，通过“保存基础记录”独立保存，反馈显示在按钮旁；反应、投料、产物及文件分别保存，保存一处不会提交或清空其他区块的未保存输入。样品、文件和摘要仍与实验关联。
- `/compounds`：可“根据CAS号新建”，优先匹配本机记录、未收录时查询 PubChem，核对候选资料与结构后保存；已有记录直接打开。另支持从结构新建、手工创建、筛选、编辑、删除化合物；详情按页查看实验、反应、样品来源。点击“多选”可勾选化合物或全选本页，输入标签名称后批量创建并添加；同名标签自动复用，原标签保留。翻页或改变筛选时清空选择。
- `/compounds/import`：在 Chrome 或 Safari 粘贴 ChemDraw 的 MOL、SMILES、CDXML 文本，或选择结构文件；本机生成结构图、分子式、分子量、精确质量和 InChIKey，提示同结构记录。点击“查询 CAS 与理化性质”后才向公开服务发送 InChIKey；CAS 号和实验性质由用户核对后选择保存。
- `/samples`：创建、查找、编辑、删除与恢复样品。
- `/files`：按实验上传和查找原始文件，下载、编辑元数据、删除与恢复。单文件上限默认 100 MiB，支持 PDF、CSV、TXT、PNG、JPEG、JCAMP-DX、ZIP；多文件逐个上传。
- `/search`：实验和化合物分组搜索、独立分页和命中字段；顶部可直接搜索。
- 首页展示有效记录统计和最近五条实验、文件；实验详情可生成、复制和下载规则 Markdown 摘要。
- 实验详情可管理多个反应及投料，并查看样品与原始文件。每个反应的“产物与收率”区可记录、编辑和删除多个产物，选择已有化合物或手动建档，保存产物量、mmol、收率和备注。投料表只显示非产物、非溶剂组分，溶剂独立显示，总览同步展示产物；产物删除后可在回收站恢复。反应物可勾选“限制反应物”，同一反应仅一个且固定为 1 eq。产物计量比默认 1，表示每 1 mol 限制反应物生成的产物 mol 数；填写产物质量后按限制反应物 mmol、计量比与产物分子量自动计算收率，超过 100% 提示检查但允许保存，也可手动修改。旧记录不自动指定限制反应物、不批量重算已有收率。
- `/settings`：创建、改名和删除标签，查看六类记录回收站及恢复阻塞原因。删除标签会清除分类关联，不删除科研记录。
- 更新、删除和关联操作使用版本号；遇到冲突时刷新记录再决定如何处理。回收站仅列出自身被删除的记录。

### 反应物与投料

输入有效 CAS 号后自动查找：先精确匹配本机化合物 CAS 字段；本机无记录时才将该 CAS 号发送至 PubChem。公开结果须包含匹配的 CAS 同义词与 IUPAC 名称、化学式、分子量；取得完整 SMILES 后在本机解析，并核对分子式和 InChIKey，通过才预览并随新试剂保存结构。盐与立体信息保持完整；缺少结构或身份不一致时提示，不猜测结构。多条结果需要选择，未找到或网络失败可重试或手动填写。查询和取消不会创建化合物；点击“加入投料表”才保存新试剂及投料。本机已有记录直接复用；已有 CAS 但无结构的试剂，可在反应物编辑区或化合物详情点击“按 CAS 补全结构”。补全仅接受唯一且身份一致的结果，保留原化合物 ID、名称、代号、备注、性质及实验关联，更新结构和由结构计算的资料；不重算原投料或收率。若新试剂保存成功但投料保存失败，重试会复用已保存的试剂。

化合物统一以 CAS 号编号，名称采用系统命名；原名称保留为独立“代号”，可按名称、代号、CAS 或 SMILES 搜索。系统不再分配 CMP 编号。查不到可核实 CAS 的记录显示“CAS 待确认”。联网资料和现有记录核验结果见 [化合物身份规范](docs/compound-identity.md)。

“限制反应物”小勾选框与角色、eq、mmol、投料量、单位同排，勾选后固定 1 eq。同一反应优先按已勾选限制反应物的 mmol 确定 1 eq；没有限制反应物时沿用首次填写有效 eq 和 mmol 的比例。输入 eq 立即换算 mmol，再按 Mw 生成当前质量单位的投料量；直接修改 mmol 或质量也会同步相关数值，允许手动调整。首次没有基准时需填写一组 eq 与 mmol（或质量和 Mw）。体积始终手动填写，不从 mmol 推算，也不从体积推算 mmol。新建或编辑界面不再显示 Mw 补全按钮和换算说明。旧记录的 g、kg、µg 和 L、µL 在表内分别换算成 mg、mL，仅改变展示，不改写保存的数值或单位。

交互参考与验证边界见 [投料表说明](docs/reactant-table.md)。

### ChemDraw 结构导入

在 ChemDraw 中选中单个分子，使用 **Copy As → MOL** 或 **Copy As → SMILES**，然后在结构导入页粘贴。也可导出 `.mol`、单记录 `.sdf`、`.smi` 或 `.cdxml` 后选择文件。浏览器可能只向网页提供普通复制的图片或专有剪贴板格式；此时请用 Copy As 或文件导入。含 R 基、查询原子、多分子结构或多记录 SDF 需要先整理成单一明确结构。

分子式、分子量、精确质量和 InChIKey 根据导入结构在本机计算。密度、熔点、沸点等是条件相关的实验资料，不能仅由二维结构可靠确定；查询结果会保留来源和原始文字，需人工选择。CAS Common Chemistry 查询需要向 CAS 申请 API 密钥并在 `.env` 设置 `CAS_COMMON_CHEMISTRY_API_KEY`；未配置时仍可查询 PubChem，PubChem 同义词中的 CAS 仅显示为待核对候选。未发表结构可以跳过公开查询。替换结构会重新计算结构资料并清除旧结构对应的 CAS 与实验性质。

页面上的一般数值（包括分子量、反应条件、用量、浓度与收率）最多显示 2 位小数，精确质量最多显示 4 位小数；不足的位数不补零。有来源的理化性质原文保持原样。此规则只用于展示，保存的计算值和用户输入值不会因此截断；编辑框去除数据库补出的尾零，但保留原有非零位数。

## 停止与数据边界

普通停止不会删除 PostgreSQL 命名卷或 `data/uploads`：

```sh
docker compose down
```

不要把 `docker compose down -v` 当作常规停止命令；它会删除数据库卷。原始上传文件和数据库必须一起备份。

## 数据检查、备份与恢复

先确认 `.env` 中的 `UPLOAD_HOST_ROOT` 与运行中后端实际挂载目录一致。默认项目名为 `rdms`；下面的路径示例需按本机配置调整。备份时工具会短暂停止前端与后端写入，并在成功或失败后恢复原运行状态；目标目录必须尚不存在。

```sh
python3 scripts/rdms_data.py check --project rdms --upload-root ./data/uploads --full-hash
python3 scripts/rdms_data.py backup --source-project rdms --source-upload-root ./data/uploads --destination ./backups/manual-20260924
python3 scripts/rdms_data.py verify --backup ./backups/manual-20260924
```

收率迁移 `e5b8d0f302ca` 只增加限制反应物标记与产物计量比，不重写原记录；保存过新标记或计量比后，直接降级会拒绝丢失内容，需从迁移前备份隔离恢复。

记录本迁移 `b8e1f3c605ad` 按授权重新编号并放弃旧编号，拒绝直接降级。迁移前备份为 `backups/pre-notebooks-20261011`；完整回退须从备份隔离恢复并配合迁移前 Git 基线 `78b99ea`，不能只回退代码。

反应条件迁移 `c9e2f4a601bd` 仅新增字段，保留旧摄氏度/小时数；已有描述或分钟记录时拒绝直接降级以避免丢失内容。需要回退时按下述步骤从迁移前备份隔离恢复。

恢复只接受新的 Compose 项目名、空上传目录和未占用的本机端口；它不会覆盖现有数据库卷或文件。验证备份后会恢复数据库和原件、再次比对所有文件哈希，再启动服务。下例是隔离演练，实际操作应换成新目录和项目名：

```sh
python3 scripts/rdms_data.py restore --backup ./backups/manual-20260924 --target-project rdmsrestore --target-upload-root ./data/restore-uploads --port 18081
```

`check` 只报告缺失、大小/哈希不符、孤立文件与临时残留，不自动修复。备份包的 `SUCCESS` 只有在备份和源服务恢复都成功后写入；失败时请查看目标目录的 `failure.log`。

## 依赖用途

后端使用 FastAPI/Pydantic Settings 提供 API 和配置，SQLAlchemy/psycopg 连接 PostgreSQL，Alembic 管理迁移，Pillow 校验图像，RDKit 解析和描绘化学结构，Uvicorn 提供服务；Ruff、mypy、pytest/httpx 用于检查。前端使用 React、React Router、TanStack Query、Tailwind CSS 与 shadcn/ui 兼容的 Radix/CVA 组件结构；Vite 构建，ESLint、TypeScript、Vitest 与 Testing Library 检查，openapi-typescript 生成接口类型。

## 当前限制

- 备份需手动执行，不提供定时备份或自动清理；恢复只接受新项目和空目录。
- 仅供本机个人使用，前端只监听回环地址。
- 本机个人使用边界固定为回环地址；不得直接改成局域网或公网监听。

实验不再提供标签选择、筛选或列表列，新建及复制实验不带入标签；保存实验不提交标签字段，旧关联保留。化合物标签继续使用。

统一备注迁移 `f6c9e1a403db` 仅新增可空列，不改写旧操作/观察/结果/结论。旧记录在备注未保存前按原分类合并显示，保存仅写新备注列；备注为空字符串时保持为空，不重新拼接旧内容。统一备注不随实验复制，以免带入观察和结论；旧操作字段仍沿用原复制规则。已有统一备注时拒绝直接降级，需要从迁移前备份隔离恢复。
